# Codex 任务自动化

任务自动化现已支持 Codex、Claude Code 和 DSH。多 Agent 设置、能力边界、会话显示诊断见 [多 Agent 任务自动化](agent-automation.md)；本文保留 Codex 的额度与协议细节。

入口：桌宠 → 工作台 → **任务自动化**。规则默认关闭。选择或粘贴 Codex 会话 ID，分别选择触发条件与动作，填写限制后启用。

## 条件和动作可以分别选择

触发条件包括本轮正常完成、任务结束或中断、明确的额度耗尽终止、相关额度恢复、网络或临时服务错误最终失败、其他明确失败，以及中断。正常完成不算中断。「任务结束或中断」统一覆盖正常完成、主动停止、额度耗尽和其他明确失败；等待回复、重连及状态未确认不属于结束。

先选择执行动作，再填写对应选项：续跑和等待额度恢复后续跑显示可选的继续指令；新任务显示必填任务内容及工作目录；关机显示倒计时和空闲条件，隐藏指令及目录。额度桶只在相关的额度条件下出现。隐藏的输入不会作为规则参数保存。

动作包括：

- **继续原会话 / 重试**：通过本机 Codex CLI 按 session ID 发送继续指令后续聊。指令可留空，此时发送默认指令，仍会产生新消息。已核对本机 App Server 协议和官方文档，未发现可稳定调用、等同桌面「继续」按钮的无消息续跑接口；`thread/resume` 只负责载入会话，不会自动开始推理。
- **挂起，确认额度恢复后继续**：保存续跑请求，等待相关额度的最新数据确认恢复。这里不主动中断正在运行的 Codex；触发来源应是已经停止的任务。
- **开始新任务**：在指定目录或来源会话目录启动新的 Codex CLI 任务，使用填写的任务内容。
- **关机**：等待至少 60 秒，可在「执行与等待」取消。默认还会等待所有已观察到的运行中、状态未确认、待回复会话结束；可在规则中取消此限制。不强制关闭未保存的应用。

例如，为同一会话配置「明确因额度耗尽停止 → 挂起，确认额度恢复后继续」，也可以改为「明确因额度耗尽停止 → 关机」。条件与动作没有写死绑定。直接选择额度耗尽后继续或启动新任务时，也会先等待额度恢复。

## 执行限制

- 次数在动作排队时累计，取消的动作也计入上限。需要再次使用时点「重置次数」。默认续跑最多触发 3 次，新任务和关机最多 1 次。
- 继续动作按累计次数增加等待时间，上限为所填延迟的 16 倍。持续失败不会无限重试。
- 同一会话不会由自动化并发续写。执行前会刷新日志；发现用户已经开始新回合或正在等待回复，会取消旧的待执行动作。
- 规则编辑、停用或删除会取消对应的待执行动作，不中断已经运行的 CLI。
- 历史回填不触发动作。同一回合的终止事件会持久化去重。
- 重启后不重放关机、延迟执行或结果未确认的运行中动作；等待额度的请求保留。待执行动作 7 天后过期。
- 后台 CLI 会沿用日志中可取得的提供商和模型；不添加绕过审批或沙箱的参数。启动成功不算任务成功，必须同时取得完成事件与成功退出码。

## 额度确认

额度匹配提供商与额度桶。主、次窗口都会检查；数据必须在阻塞之后产生，且仍足够新。仅仅到达预计刷新时间、旧窗口已经过期、查询失败或返回空数据，都不会触发继续。

需要等待时，每分钟尝试用本机 `codex app-server` 的只读账号接口查询一次，也可以手动查询。账号查询只用于当前 `openai` 提供商下的 ChatGPT 登录。自定义提供商即使仍能读取 ChatGPT 账号额度，也不能用它证明自定义提供商额度恢复；普通 rollout 也可能保留这些账号额度。因此自定义提供商的快照还必须在额度数据本身明确标注匹配的 `model_provider`，否则保持挂起。没有这些数据的自定义提供商需要另接其额度接口，当前不能自动确认恢复。不消耗账号的额外重置权益。

## 状态来源的边界

现有桌面和 CLI 会话继续通过本地 rollout 监听。只有日志实际包含明确终止信息时，才能区分失败原因。未明确终止的错误记为「观察到错误，尚未确认终止」，不会启动外部重试。某些 Codex 版本不把全部客户端错误写入 rollout，因此无法承诺覆盖这些版本的所有错误。

LLMPET 启动的自动任务另外读取 CLI JSON 事件并跟踪进程退出，可以获取其最终结果。网络重连、等待审批、桌宠超时回到空闲都不是正常完成。「本轮正常完成」表示一次回复结束，不验证整个项目目标是否达成。

规则、待执行动作、次数、事件去重及最近记录保存在 `~/.octopus/codex-automation.json`，文件无法读取或保存时暂停执行，不覆盖坏文件。`LLMPET_AUTOMATION_STATE` 可指定独立状态文件做开发验证。

`LLMPET_NO_CODEX=1` 停用 Codex 监听及 Codex 自动调度，不影响其他 Agent。`OCTOPUS_NO_NET=1` 禁止自动模型任务联网及账号额度查询；本地关机动作仍可使用。

## 验证

`npm test` 包含自动化引擎、配额匹配、重启去重、取消、限次、watcher 和执行器测试。

`npm run test:automation-ui` 使用真实 Electron 启动整个应用，在独立临时目录验证主进程 / preload / 工作台 IPC、两个额度耗尽动作、关机取消、中英日界面及窄窗口布局。测试禁止实际模型任务与关机。
