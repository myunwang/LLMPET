# Codex 任务自动化

任务自动化支持 Codex、Claude Code 和 DSH。入口：桌宠 → 工作台 → **任务自动化**。多 Agent 状态来源与扫描诊断见 [多 Agent 任务自动化](agent-automation.md)。

## 配置与管理

选择来源 Agent，再从「已发现会话」点击「选择」，或粘贴会话 ID。列表支持按标题或 ID 搜索。保存后显示「保存成功」。规则默认关闭，勾选启用后才会执行。

「已保存规则」同时显示规则名称、任务标题和会话 ID。点击「重新选择对话」，再点击一个已发现会话的「选择」，会直接替换该规则的对话并保存；规则 ID 和其他设置保留，新会话的标题、目录、模型与提供商随选择更新。也可以通过「编辑」修改后保存。

已保存规则位于已发现会话上方。已发现会话默认显示五条，点击「展开全部」后显示当前 Agent 的全部匹配记录，可再次收起。输入会话 ID 时暂停更新原生下拉选项，避免输入、每秒倒计时或后台状态推送把选择列表关闭；失去焦点后更新候选列表。

## 条件和动作

触发条件包括：

- **指定时间**：按本机时区选择日期与时间，到点执行一次。页面显示当前时区，保存的是绝对时间，不依赖后续日志事件。请保持 LLMPET 运行。
- **5 小时额度恢复（ChatGPT 账号）**、**每周额度恢复（ChatGPT 账号）**：分开观察 300 分钟、10080 分钟窗口，首次读取仅建立基线。确认从 100% 恢复可用，或旧窗口已过期且最新查询返回新的重置窗口后触发。查询失败、陈旧数据和仅到达预计时间均不触发。
- **本轮正常完成**：一次回复正常结束，不验证整个项目目标是否达成。
- **任务结束或中断**：包括完成、主动停止、额度耗尽及其他明确终止。
- **网络 / 临时服务错误最终失败**、**其他明确失败**、**任务中断**。

额度恢复条件监测已登录的 **ChatGPT 账号额度**，支持 `account/rateLimits/read` 的多额度桶返回，默认使用 `codex` 桶。页面显示两个窗口的使用比例、重置时间和采样时间，可手动刷新；启用额度规则后每分钟查询。自定义提供商下仍可读取账号额度，触发条件明确属于 ChatGPT 账号，执行仍沿用原会话的提供商和模型，不把账号额度当成自定义提供商可用性的证明。两个窗口分别恢复不保证其他额度或消费限制同时解除。接口说明见 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。

动作包括：

- **继续原会话 / 重试**：自动检测 Codex 桌面端。运行时通过桌面原生 App Tools 向原会话发送跟进指令；未运行时使用本机 `codex exec resume`。留空使用默认继续指令。执行与等待卡片显示「桌面原生」或「CLI」。桌面原生跟进在历史中可能表现为委派工具输入，仍使用原会话并产生新回合。
- **开始新任务**：任务内容必填；可指定目录，留空使用来源会话目录。桌面运行时在匹配的已有本地项目中创建新任务，目录未加入桌面项目时会提示；桌面未运行时使用 CLI。
- **关机**：状态触发的关机至少有 60 秒倒计时；定时关机必须设在至少 60 秒后。默认等待运行中及待回复会话结束；等待结束后重新给予至少 60 秒取消窗口。可在「执行与等待」取消，不强制关闭未保存的应用。

定时动作隐藏延迟和次数输入，固定执行一次。事件动作可设置延迟和次数：继续默认最多 3 次，新任务和关机默认最多 1 次。隐藏的指令、目录输入不会作为动作参数保存。

## 调度限制

- 卡片显示**成功完成次数**：排队、取消、失败和等待写入锁均不增加。自动尝试另有同样的次数上限，避免失败无限循环；重置会清零成功次数与尝试次数。排队时也能重置，保留一个待执行动作；执行中需等待结束。已过期的定时计划重置后不会补执行，应设置新的未来时间再保存。取消的定时计划不会自行重新排队。旧版排队计数迁移为对应动作的实际成功数。
- 事件触发的继续动作按累计次数增加等待时间，上限为所填延迟的 16 倍。
- 同一会话不会由自动化并发续写。事件重试排队后若用户开始新回合，会取消旧重试；定时动作保留，到点会等待会话空闲。
- 编辑、停用、删除规则会取消对应待执行动作，不中断已运行的 CLI。
- 历史回填不触发事件动作，同一回合的终止事件持久化去重。
- 重启保留尚未到点的定时计划；错过执行时间、已运行或结果未确认的动作取消，不补执行。到期后等待超过 7 天的动作过期。
- 桌面原生发送使用本机 Codex 内置 `codex-app-tools` 命名管道，不启动第二个 App Server，不修改 Codex 安装包。Windows 可自动枚举管道，支持桌面重启后旧环境变量失效的情况。仅当确认桌面端未运行才回退 CLI；桌面运行但通道不可用时显示「等待桌面发送通道」，每 30 秒重试。
- 原生发送确认回包失败时不会重复提交，会查询新增回合并核对原指令；只有匹配回合完成才计成功。目标原本仍在运行时等待，避免打断用户。提交后连接断开且无法核实时显示「提交或完成状态未确认」，不自动重复发送；可打开原会话核实。
- CLI 标准错误会保留并脱敏。桌面未运行但其他 CLI 持有写入锁时仍需等待，期间不消耗次数。
- CLI 沿用来源会话中可取得的模型与提供商，不添加绕过审批或沙箱的参数。必须同时取得完成事件与成功退出码才报告成功。

## 旧规则迁移与数据

旧额度规则保留名称、来源会话和指令，转为**停用的指定时间规则**，显示「请重新设置执行时间后启用」。旧额度等待动作取消，其他规则照常保留，不自动猜测恢复时间。

规则、动作、次数、去重与记录保存在 `~/.octopus/codex-automation.json`。文件读取或保存失败时暂停执行，不覆盖坏文件。`LLMPET_AUTOMATION_STATE` 可指定独立状态文件。

`LLMPET_NO_CODEX=1` 停用 Codex 监听和调度。`OCTOPUS_NO_NET=1` 禁止自动模型任务联网，本地关机动作仍可使用。
